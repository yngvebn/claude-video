# Looks: the runtime contract and how to write one

A **look** is the renderer: everything you see. The rest (narration, anchors, timeline, sound, render) is shared and
look-agnostic. `project.json "look"` picks one:
- **Built-in:** `kinetic` (scenes.md), `documentary`, `whiteboard`, `cinematic` and `postmortem` (each in `looks/<name>.md`).
- **`custom`:** `projects/<p>/look.js`, written for this video from a style guide (`references/styles/`). Create the
  project with `node story.mjs new <p> --look custom` to get a working starter.

Page load order (generated by `story.mjs layout`):
`timeline.js → rough.js → kit.js → minis-ai.js → anchors.js → story.js → scenes.js → theme.js → runtime.js → the look`.

## The contract
```js
runLook({
  draw(sec, t) { ... },        // required: paint the whole frame, t = seconds into section `sec`
  fallback(say) { ... },       // scene for a section without a STORY entry (default: kinetic's word-by-word autoScene)
  init(SEC) { ... },           // once, after sections resolve: precompute layouts, star fields, meshes
  setup: async () => { ... },  // once, after fonts load: offscreen canvases, textures
  hud(sec, t) { ... } | false, // overlay after draw (default: kicker top-left + progress dots)
  enter(sec, prev, t) | false, // transition over the start of every section but the first (default: colour wipe)
});
```

## What a section gives you (`sec`)
| Field | What |
|---|---|
| `key`, `i` | section key from story.js, index |
| `a`, `b`, `d` | absolute start and end in the video, length in seconds |
| `bg`, `C` | the scene's palette name and the palette object (`theme.js`) |
| every scene field | `kicker`, `title`, anything you put on `STORY[key]` |
| `blocks` | the scene's blocks, **with times resolved**: `t0`/`t1` from `at` (start and end of the anchor words), `tout` from `out`, `t<name>` from any `<name>At` field, and `t0` / `t<name>` on object rows |
| `frames` | resolved camera frames (`t0`), if the scene has any; `cameraOf(sec, t)` flies between them |
| `words` | the narration word by word: `{ w, t0, t1, si, pj }`, display text with punctuation (exact with ElevenLabs, estimated otherwise) |
| `sentences` | `{ si, t0, t1, text, phrases: [{ t0, t1, text }] }` |

Runtime helpers: `activeSentence(sec, t)`, `wordsSpoken(sec, t)`, `cameraOf(sec, t)`, `defaultHud`, `defaultEnter`,
and `SEC` (all sections, e.g. to ghost the previous one). There's also `window.PROJECT = { name, title, source }`.

Kit helpers (engine/kit.js): `text(s, x, y, { font, size, color, align, alpha, reveal, maxW, jit })`, `measure`, `prog`,
`clamp`, `lerp`, easing `E.out / E.in / E.inOut / E.back`, `rnd(seed)`, `hash`, `mixHex`, camera `cam()`, transitions
`wipe`, `flash`, `speedLines`, `zoomLines`, hand-drawn `sketch(pts, p, id, opts, rate)`, `circlePts`, `arrow`,
`highlight`, `ro(id, opts, rate)`, sprites `drawPixels`, `drawMini`. Fonts are the families named in
`theme.js fonts`; `BG[palette]` holds a textured background per palette.

## Rules
- **Deterministic:** the same `t` must give the same pixels, because frames render in parallel and out of order.
  No `Math.random`, no `Date`, no state carried between frames (caches keyed on data are fine). Use `rnd(seed)`.
- **Wrap the look in a closure** (`const MYLOOK = (() => { ... return {...}; })(); runLook(MYLOOK);`). Top-level names
  share one global scope with the kit, runtime and project files, and a clash kills the page ("Identifier has
  already been declared").
- **Time comes from anchors,** not from constants. Beats hang on `b.t0` / `b.t<name>`. Durations are for the motion
  itself (a 0.4 s settle), never for pacing.
- **Draw the whole frame** in `draw`, background included. Alpha fades: multiply a passed-in alpha, don't reset
  `ctx.globalAlpha` to an absolute value inside a block, or ghosted and dissolving content pops back to full.
- **Fail loudly** on authoring mistakes: an unknown block kind, a missing `id`. Silent fallbacks become blank frames.
- Keep a block vocabulary document next to the look (`references/looks/<name>.md`) when it's meant for reuse.

## Writing a look from a style guide
1. Read the guide. Its Signature rows are your requirements; list them.
2. Pick the closest built-in look and copy its structure: kinetic (camera plus blocks), documentary (static stage,
   captions, cards), whiteboard (drawn-on, persistent canvas), cinematic (pre-painted parallax layers, depth, grading)
   or postmortem (a UI grid of panels with live data).
3. Palette and fonts go in `theme.js`, from the guide's hex values or the brand's real colours. Fonts are woff2 files in
   `assets/fonts` (fontsource on jsdelivr has Latin subsets; check æøå or whatever the language needs).
4. Define a small block vocabulary (4–8 kinds) that covers the guide's signature objects, and a `fallback` so
   unauthored sections still read (captions or handwritten lines).
5. Test with `VOICE=none` (free, silent): `voice`, `layout`, `qa`. Compare the sheets against the Signature rows, fix,
   then show the user a `clip` of two sections before building everything.
